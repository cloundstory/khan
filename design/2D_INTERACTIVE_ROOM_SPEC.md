# คั่น — 2D interactive room spec

## คำตอบสั้น ๆ

ใช่ครับ ฉากหลักใช้ภาพ 2D เป็นหลัก แต่ “หนังสือจริงของผู้ใช้” ไม่ควรถูกวาดติดตายอยู่ในภาพห้อง เพราะจำนวน ปก และสถานะเปลี่ยนได้ตลอด ระบบจึงใช้ภาพ 2D แบบประกอบชั้น:

```text
ภาพห้องและเฟอร์นิเจอร์ 2D
        ↓
พื้นรองตู้ / เงากอง / ช่องว่างในชั้น
        ↓
หนังสือจาก Book record จริง วาดเป็น DOM/SVG 2D
        ↓
CSS/SVG animation ตามสถานะการแตะและการอ่าน
```

ไม่มีโมเดล 3D ในฉาก Home หลัก การยก หมุน และเลื่อนหนังสือเป็นการเปลี่ยน `transform`, `opacity`, `filter` และเงาใน 2D

## แบ่ง asset เป็นสามประเภท

### 1. Room plate

เป็นภาพ 2D ที่ไม่เปลี่ยนตามข้อมูล เช่น ผนัง พื้น โซฟา ตู้ โคมไฟ และพรม ภาพพวกนี้ทำหน้าที่ให้โลกมีลายเส้นและบรรยากาศคงที่

### 2. Runtime book layer

เป็นหนังสือที่ระบบประกอบจากข้อมูลจริงของผู้ใช้ ประกอบด้วย:

- โครงสันและขอบหนังสือแบบ SVG/CSS
- สีและความหนาจาก `Book` record
- ปกจริงจาก `coverUrl` หรือรูปปกที่ผู้ใช้ถ่ายเอง
- หน้ากระดาษเป็นลายเส้นหรือ gradient ที่ code คุม
- ตำแหน่งในกอง ชั้น หรือโต๊ะจาก `status`

บนชั้นจะแสดงสันเป็นหลัก ส่วนกองจะแสดงสัน ปก ขอบกระดาษ และระยะซ้อนของแต่ละเล่ม การเปลี่ยนหรือเพิ่มหนังสือจึงไม่ต้อง generate ภาพห้องใหม่

### 3. Interaction layer

เป็นชั้นโปร่งใสที่วาดด้วย DOM/SVG และตอบสนองต่อข้อมูล เช่น:

- เข็มนาฬิกาคำนวณจากเวลาปัจจุบัน
- แสงโคมไฟและ color wash ตามสถานะเปิด/ปิด
- ท้องฟ้า ดวงจันทร์ ดาว และแสงหน้าต่างตามช่วงเวลา
- หมุด กระดาษ และด้ายแดงบน evidence board
- hit area, tooltip, focus ring และแผงรายละเอียด

## หนังสือ 2D ทำให้รู้สึกหยิบได้อย่างไร

สถานะเริ่มต้นของหนังสืออยู่ในกองหรือชั้น จากนั้นเมื่อแตะเล่มที่เลือก ระบบจะเล่นลำดับสั้น ๆ:

1. ยกขึ้นเล็กน้อยด้วย `translateY`
2. หมุนเอียงประมาณ 2–5 องศา
3. เพิ่มเงาและลดเงาของตำแหน่งเดิม
4. เลื่อนตามเส้นโค้งด้วย keyframes ไปยังโต๊ะหรือพื้นที่อ่าน
5. ขยายเป็นแผงรายละเอียดหรือหน้าอ่าน

ปกยังเป็นภาพแบน 2D แต่การแยกชั้นปก สัน หน้ากระดาษ และเงาทำให้ตาดูเห็นความหนาได้เพียงพอสำหรับ interaction นี้ ถ้าต้องการเปิดหนังสือ ใช้ภาพหน้าซ้าย/ขวาและ animation กลางสันแทนการหมุนโมเดล

## ตัวละครที่แต่งได้

ใช้ท่านั่งและ anchor เดียวกันทุกคน แล้วแยกเป็น layer:

- body presentation
- hair
- outfit top/bottom
- accessory
- blanket หรือของถือ

จุดยึดของแต่ละ layer ต้องล็อกในไฟล์เดียวกัน เพื่อให้เปลี่ยนเสื้อผ้าแล้วแขน หนังสือ และลำตัวไม่กระโดด การหายใจ กระพริบตา และขยับผมใช้ animation เบา ๆ และหยุดเมื่อเปิดแผงแต่งตัว

## UX ที่ทำเป็น mockup แรก

เปิดดูได้ที่ `/?ux-lab`:

- แตะตัวละครเพื่อเปิด drawer แต่งเสื้อผ้าและผม
- แตะหนังสือเพื่อยกออกจากกองและดูรายละเอียด
- แตะโคมไฟเพื่อสลับเปิด/ปิด
- แตะหน้าต่างเพื่อสลับกลางวัน/กลางคืน
- นาฬิกาใช้เข็มที่คำนวณจากเวลาจริง
- bottom navigation อยู่เป็นกลุ่มเล็กด้านล่าง ไม่บังตัวละครหรือกองหนังสือ

## Mobile flow prototype ที่ผ่านการตรวจ

หน้า `/?mobile-flow` เป็น prototype ของเฟส 0–1 ที่ใช้ข้อมูลตัวอย่างใน React state เพื่อทดสอบ navigation ก่อนผูก IndexedDB จริง:

```text
Home → กองอยู่ → เลือกหนังสือ → เริ่มอ่าน → Timer
                         └────→ อ่านจบแล้ว → ชั้น
Home → โซฟา → Timer
Home → โต๊ะ → Progress
Home → evidence board / ตัวละคร / แมว
```

Prototype นี้ตรวจบน viewport มือถือ `390×844px` แล้ว โดยแตะกอง เปิดรายการ เลือกเล่ม และย้ายเข้าสู่ Timer ได้จริง การเพิ่มหนังสือใน prototype เป็นข้อมูลตัวอย่างเท่านั้น; เฟสถัดไปจะเปลี่ยนเป็น `addBook()` ที่เขียนเข้า IndexedDB และใช้ cover photo ของผู้ใช้

การปรับล่าสุดของเฟส 0–1:

- Home ซ่อนปุ่มและการ์ดสรุปทั้งหมด เหลือเพียงจุดแตะบนวัตถุในฉากจริง พร้อมปุ่มตั้งค่าเพียงจุดเดียว
- Timer เปลี่ยนเป็น stopwatch แบบนับขึ้นต่อเนื่อง แตะตัวเลขเพื่อพัก/อ่านต่อ และกด `จบ session` เพื่อกลับไปหน้าบนโต๊ะ
- ปัดขึ้นจากหน้า Timer เพื่อเปิด evidence board ได้ทันที โดยยังมีแถบจับเป็น affordance สำหรับอุปกรณ์ที่ไม่ได้ปัด
- evidence board, ชั้น, กอง และโต๊ะยังคงเป็นหน้าปลายทางแยกกัน เพื่อให้ logic ของหนังสือไม่ปะปนกับฉาก Home

หน้า mockup ใช้ตัวละคร CSS เป็น placeholder เพื่อทดสอบ UX เท่านั้น เมื่อ flow ผ่านจึงค่อยแทนด้วย PNG/SVG ที่วาดด้วย line grammar เดียวกับฉาก

## ขอบเขตที่ยังไม่ทำใน mockup

- ยังไม่เชื่อม `Book` จาก IndexedDB จริง
- หนังสือใน mockup ใช้ปกตัวอย่างและโครง CSS
- ตัวละครยังไม่ใช่ asset final
- แสงหน้าต่างยังเป็น state กลางวัน/กลางคืนแบบสองสถานะ ก่อนขยายเป็น timeline dawn/day/dusk/night
